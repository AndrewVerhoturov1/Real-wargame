# Маршруты Codex/OpenCode для Real Wargame

Русский справочник по маршрутам выполнения задач: **A, B, C, D, L, Q, R, W, X**.

Документ объясняет, какой маршрут когда выбирается, как он работает, что в нём
разрешено и запрещено, какие есть переходы, остановы и навыки, а также чем этот
набор маршрутов отличается от игровых «маршрутов» Real Wargame (пути движения,
навигация, pathfinding). Для внешнего агента с доступом только к GitHub есть
отдельный готовый пакет: `docs/ai/OPENCODE_ROUTES_EXTERNAL_Q.md`.

## 1. Что это и зачем

Codex выступает оркестратором и независимым проверяющим. Сама работа с локальным
репозиторием, файлами, командами и проверками выполняется через OpenCode или
через внешних исполнителей. Маршрут — это выбранный для конкретной фазы способ
выполнения работы. Одна задача пользователя обычно использует несколько маршрутов
последовательно (цепочку маршрутов), а не один маршрут на всю задачу.

Главный источник по маршрутам (локальный диспетчер) запрещает Codex самому
выполнять локальную работу с репозиторием по умолчанию: чтение, поиск, список,
правки, проверки и Git-операции выполняются через OpenCode. Подробности — в
разделе «Источник сведений» в конце.

## 2. Быстрая сводка: таблица маршрутов

| Маршрут | Тип | Что делает | Результат | Когда выбирается |
|---|---|---|---|---|
| **A** | автоматический, стандартный | OpenCode/DeepSeek: разведка, чтение, контекст, проверки, мелкие безопасные правки | TASK_STATUS + компактное доказательство | по умолчанию для обычной локальной работы и любой разведки перед выбором маршрута |
| **B** | запасной (fallback) | перезапуск через job-wrapper после реального сбоя прямого маршрута | то же, что A | только после реальной проблемы прямого маршрута в текущей задаче |
| **C** | специализированный | тяжёлая локальная реализация/ремонт через minimax-m2.5 (ollama_5_round_robin) | ограниченный локальный результат + доказательство | фаза требует «локальных рук», которые A не вытягивает, а W/X не видят контекст |
| **D** | специализированный, только по явной просьбе | нативные модели самого Codex | результат прямой фазы | пользователь явно просит «нативные модели Codex / Route D»; также всегда для `comfyui-mcp` |
| **L** | автоматический, узкий | точечный микро-патч на уже готовом ограниченном контексте | одна очевидная правка + один известный безопасный чек | весь контекст уже явный и ограниченный, не нужен поиск |
| **Q** | ручной | ручной внешний GitHub-агент: ветка + PR + отчёт | ветка + PR + отчёт + поля навыков | пользователь явно просит ручной GitHub-aware внешний запрос |
| **R** | ручной | ручной `/zworker`: внешний чат → ZIP с `answer.md` | ZIP с `answer.md` | пользователь явно просит `/zworker` |
| **W** | автоматический | автоматический ZIP-маршрут: Codex → ChatGPT Web → ZIP | ZIP с `answer.md` | X недоступен/не подходит, нужен ZIP, репозиторий не collaborative |
| **X** | автоматический | автоматический GitHub-маршрут: Codex → внешний агент → ветка + PR + терминальный маркер | ветка + PR + отчёт + верификация | несложная… нет, **сложная** работа в collaborative-репозитории; явный `/X` |

Правило приоритета для A и L: если одна и та же готовая ограниченная фаза
подходит и A, и L — выбирается L. Любая неуверенность возвращает фазу к A.

## 3. Детали маршрутов

Форматы для каждой строки: назначение, селектор (как выбирается), триггеры,
рабочий процесс, входы/выходы, разрешено, запрещено, модель/инструмент,
переходы, останов/блокировка, навыки, значение для Real Wargame.

### 3.1 Маршрут A — стандартный OpenCode/DeepSeek (автоматический)

| Поле | Значение |
|---|---|
| Назначение | Маршрут по умолчанию для разведки, чтения, картирования, проверок и мелких низкорисковых правок. Обязателен для разведки репозитория перед выбором следующего маршрута. |
| Селектор | Первый выбор для обычной локальной фазы. Если выбор маршрута зависит от фактов репозитория — эти факты собирает именно Route A. |
| Триггеры | поиск по репозиторию; многофайловое чтение; `context_pack`; подготовка промта; анализ конфигов/логов/ошибок; сводка diff; проверка изменённых файлов; `verify_pack`; разбор ZIP и безопасная проверка; выбранные Codex локальные проверки; очевидные мелкие правки без новой логики. |
| Рабочий процесс | `Codex -> mcp__opencode.* -> OpenCode -> deepseek/deepseek-v4-flash`. Режимы задач: `context_pack` (только чтение, компактный вывод), `patch_pack` (маленькая разрешённая правка), `verify_pack` (проверка состояния/diff/проверок без правок). |
| Входы/выходы | Вход — ограниченный промт с полями MODE / GOAL / SCOPE / MUST DO / MUST NOT / STOP BEFORE / OUTPUT / BUDGET. Выход — один валидный `TASK_STATUS` в начале ответа и компактное доказательство (изменённые файлы, сводка diff, проверки, риски). |
| Разрешено | разведка, чтение, контекст, подготовка промтов, анализ, проверки, `verify_pack`, маленькие правки «без новой логики», выбранные безопасные локальные команды после решения Codex. |
| Запрещено | средние и крупные реализации «только потому, что разведка шла через A»; локальные Git-записи; прямые GitHub-инструменты Codex (GitHub всегда через OpenCode); секреты и `.env`; взаимодействие с `comfyui-mcp` (это специальный маршрут D). |
| Модель/инструмент | `mcp__opencode.*`; модель по умолчанию `deepseek/deepseek-v4-flash`, запасные `opencode/deepseek-v4-flash-free`, затем `opencode/mimo-v2.5-free`. |
| Переходы | A → L (готовая ограниченная микро-правка); A → GitHub-control (GitHub-работа); A → X/W (сильное внешнее мышление); A → C (тяжёлый локальный ремонт). Подтип A-journal — документальный подтип A для сессионных артефактов. |
| Останов/блокировка | если вся цепочка запасных моделей тоже сбоит/пуста — остановиться и объяснить блокер; лимит вызовов OpenCode/MCP: цель 2–4, жёсткий потолок 6; статусы `BLOCKED`, `BLOCKED_PERMISSION`, `NEEDS_CODEX_DECISION`. |
| Навыки | диспетчер `opencode-mcp-windows-control` (источник по маршрутам); `opencode-github-mcp-control` для GitHub; условные навыки подгружаются только когда маршрут/тип задачи требует. |
| Real Wargame | каждая задача начинается с разрешения точного HEAD `real-wargame-preview`, чтения канонических документов через A и создания feature-ветки. Текущая документационная работа выполняется по маршруту A. |

### 3.2 Маршрут B — запасной «колокол» через job-wrapper (fallback)

| Поле | Значение |
|---|---|
| Назначение | Ограниченное восстановление, когда стандартный маршрут уже показал реальную проблему в текущей задаче. Не новый маршрут по умолчанию. |
| Селектор | Только после реальной проблемы прямого маршрута в текущей задаче (таймаут, пустой/безтекстовый ответ, занятая/застрявшая сессия, пропущенный финальный ответ, спираль check/wait). |
| Триггеры | таймаут; пустой или без текста ответ; занятая или застрявшая сессия; отсутствие финального ответа; иначе потребовалась бы спираль check/wait. |
| Рабочий процесс | одна ограниченная попытка: `Codex -> mcp__opencode_jobs.opencode_job_run_and_wait -> job-wrapper -> OpenCode`. После успеха следующая новая задача снова стартует со стандартного `mcp__opencode.*`. |
| Входы/выходы | как у A, но одна ограниченная попытка восстановления; выход — TASK_STATUS и доказательство. |
| Разрешено | одна ограниченная попытка восстановления текущего сбоя; одно целевое обнаружение инструмента (`tool_search`) для `opencode_job_run_and_wait`, если он ещё не доступен. |
| Запрещено | превращение B в маршрут по умолчанию; повторные check/wait-спирали как нормальный способ ожидания; смешивание с другими маршрутами. |
| Модель/инструмент | `mcp__opencode_jobs.opencode_job_run_and_wait` → job-wrapper → OpenCode. |
| Переходы | B → следующая новая задача снова через стандартный A; если B тоже сбоит — остановка и отчёт. |
| Останов/блокировка | если инструмент недоступен и единичный поиск не помог — сообщить, что маршрут недоступен; после одной проверки + одного короткого ожидания + одной попытки чтения результата без успеха — остановиться. |
| Навыки | раздел про fallback «колокол» в `opencode-mcp-windows-control`. |
| Real Wargame | B — только восстановление; правила доставки (feature-ветка, без прямых правок в preview) не меняются. |

**Наблюдаемый риск окружения (2026-08-21).** В этот день job-wrapper (обёртка
задач) при попытке использовать маршрут B/C обратился к выведенной из
эксплуатации модели `minimax-m2.5`. Это наблюдение окружения, а не придуманное
универсальное правило: у разных установок job-wrapper может вести себя иначе.
Правило остаётся прежним: если провайдер/модель/обёртка/результат недоступны,
пусты, вне области или непригодны — остановиться и объяснить блокер, а не молча
переключать модель.

### 3.3 Маршрут C — minimax-m2.5 через ollama_5_round_robin (OpenCode Jobs)

| Поле | Значение |
|---|---|
| Назначение | Ограниченная тяжёлая локальная реализация или ремонт. Не маршрут «самого сильного мышления» по умолчанию. |
| Селектор | Выбирается планированием по фазам, когда фазе нужны локальные «руки», которые A надёжно не вытягивает, а W/X не должны или не могут видеть нужный контекст. Отдавать предпочтение C при двух и более сигналах: сложная локальная проверка; падающие сложные тесты; пост-Web локальный ремонт; локальный контекст новее GitHub и непубликуем; длинная ограниченная локальная работа, где A слишком слаб. |
| Триггеры | `patch_pack` сложной задачи; сложная локальная верификация/ремонт; одна одобренная трудная ошибка; пост-Web очистка/ремонт, когда принятый вывод требует локальных правок. |
| Рабочий процесс | Codex сначала собирает минимум контекста через A, затем отправляет одну ограниченную задачу: `Codex -> mcp__opencode_jobs.opencode_job_run_and_wait -> job-wrapper -> OpenCode -> ollama_5_round_robin/minimax-m2.5`. |
| Входы/выходы | Вход: MODE `patch_pack` + GOAL/SCOPE/MUST DO/MUST NOT/STOP BEFORE/OUTPUT/BUDGET. Выход: TASK_STATUS первым, изменённые файлы, компактная сводка diff, проверки, риски. |
| Разрешено | ограниченный локальный срез реализации; сложная локальная проверка; ремонт после Web; длинные ограниченные локальные задачи. |
| Запрещено | начальная широкая разведка; расплывчатые задачи; рефакторинг всего репозитория; изменение зависимостей; install/network/server/watch команды; секреты и `.env`; постоянные правки конфигурации OpenCode; Git/GitHub-записи; задачи больше одной ограниченной попытки; молчаливый переход на Kimi, Flash, локальный Codex или старый мост. |
| Модель/инструмент | `ollama_5_round_robin` / `minimax-m2.5` через `mcp__opencode_jobs.opencode_job_run_and_wait`. Название навыка устаревшее: `opencode-deepseek-pro-jobs-control`. |
| Переходы | A собирает контекст → C реализует/чинит → A проверяет результат. |
| Останов/блокировка | если провайдер, модель, job-wrapper или результат C недоступны/пусты/вне области/непригодны — остановиться и объяснить блокер; никогда не молча переключаться на Kimi, Flash или локальный Codex. |
| Навыки | `opencode-deepseek-pro-jobs-control` — читать перед использованием Route C. |
| Real Wargame | C — только ограниченные тяжёлые локальные работы; исправления продукта остаются на feature-ветке. |

### 3.4 Маршрут D — нативные модели Codex (только по явной просьбе)

| Поле | Значение |
|---|---|
| Назначение | Работа на нативных моделях самого Codex вместо OpenCode, ChatGPT Web, MiniMax-jobs или job-wrapper. |
| Селектор | ТОЛЬКО по явной просьбе пользователя: «нативные модели Codex», «использовать Codex напрямую», «Route D». Никогда не выбирается автоматически. Специальное правило ComfyUI: каждое прямое взаимодействие с `comfyui-mcp` (обнаружение, `list_packs`/`skill_list`, чтение навыков, вызовы MCP) — это автоматический маршрут D даже без фразы «Route D». |
| Триггеры | явная просьба про нативные модели/прямой Codex/Route D; прямое взаимодействие с `comfyui-mcp`. |
| Рабочий процесс | Codex выполняет запрошенную фазу напрямую своими нативными моделями. |
| Входы/выходы | как у фазы; в отчёте: что сделано нативно, какие локальные действия и с каким явным разрешением, какие GitHub/удалённые действия и каким разрешённым маршрутом. |
| Разрешено | нативная работа Codex для явно запрошенной фазы; прямое взаимодействие с `comfyui-mcp`. |
| Запрещено | авто-выбор D без явной просьбы; трактовка D как обязательного шлюза для создания/правки навыков; трактовка действий L как D; доступ к локальным файлам без явного разрешения на это точное действие; прямые GitHub-инструменты Codex; Git-записи без разрешения; молчаливая подмена других транспортов ради «удовлетворения» запроса D. |
| Модель/инструмент | нативные модели Codex. |
| Переходы | D применяется только к той части задачи, для которой пользователь явно попросил нативные модели; остальные фазы сохраняют обычные маршруты. |
| Останов/блокировка | нет явной просьбы — не выбирать D; нужно локальное действие без разрешения — остановиться и спросить; решение неясно — спросить пользователя, а не гадать. |
| Навыки | `d-route-control` — читать перед использованием Route D. Route L никогда не подгружает `d-route-control`. |
| Real Wargame | даже в D GitHub-работа остаётся OpenCode-опосредованной; правила репозитория не отменяются. |

**Важно.** Навык `@Superpowers` — это процессный навык (метод работы), а не
выбор Route D. Наличие или подключение `@Superpowers` не означает и не заменяет
явную просьбу пользователя про нативные модели Codex / Route D.

### 3.5 Маршрут L — узкий автоматический микро-патч на готовом контексте

| Поле | Значение |
|---|---|
| Назначение | Автоматический, узкий, строго ограниченный путь нативного Codex для уже известного и явного контекста. Работает на любой активной нативной модели Codex; не требует проверок Luna/Terra/Sol. |
| Селектор | Применяется ТОЛЬКО когда весь нужный контекст уже явный и ограниченный: явно названные известные файлы, предоставленный фрагмент/сводка, готовый `context_pack` или достаточный срез Route A; не нужен поиск по репозиторию, широкое чтение, обнаружение или сложная диагностика; при правке — не более одной очевидной правки в одном известном файле, без новой подсистемы и без нетривиальной логики. |
| Триггеры | чтение явно названных известных файлов без поиска; объяснение предоставленного фрагмента; выбор следующего маршрута из готового `context_pack`; ограниченная классификация UI/backend и tiny/medium; финальная подготовка промта для X/W/Q; одна очевидная точечная правка в одном известном файле; один уже известный безопасный неразрушающий чек; узкая проверка собственной правки L в пределах этого одного чека. |
| Рабочий процесс | прямое узкое нативное действие Codex на готовом контексте. |
| Входы/выходы | явный ограниченный вход; выход — узкий результат и доказательство. |
| Разрешено | только перечисленные узкие действия выше. |
| Запрещено | рекурсивный поиск; широкое/неограниченное чтение; создание `context_pack`; сложная диагностика; средняя/крупная реализация; архитектурные решения; зависимости/сеть/серверы/watch/секреты; Git и GitHub-операции; очистка; обязанности X/W/C/GitHub/cleanup/report. |
| Модель/инструмент | любая активная нативная модель Codex; без проверок Luna/Terra/Sol. |
| Переходы | A ↔ L; если контекст не известен/явен/достаточен — L неприменим и нужен A; если задача выросла за перечисленные действия — перестать считать её L и перевыбрать маршрут. |
| Останов/блокировка | контекст не готов и не ограничен — L не применяется, вернуться к A; выход за перечисленные узкие действия — прекратить L. |
| Навыки | отдельного контрольного навыка нет (правила в диспетчере); L никогда не подгружает `d-route-control`. |
| Real Wargame | L не используется для средних работ по продукту; L — это не D и не смягчает правило «D только по явной просьбе». |

### 3.6 Маршрут Q — ручной GitHub-aware внешний запрос (пользовательский)

| Поле | Значение |
|---|---|
| Назначение | Ручной режим внешнего запроса к GitHub-aware агенту. Управляется пользователем; Codex не выбирает Q автоматически. |
| Селектор | Только когда пользователь явно просит ручной GitHub-aware внешний запрос / Route Q. |
| Триггеры | явная просьба пользователя; подготовка Q-пакета оркестратором. |
| Рабочий процесс | Codex готовит промт-пакет с `Required Skills Manifest`; пользователь передаёт пакет внешнему GitHub-агенту; агент работает через GitHub и возвращает ветку + PR + отчёт; результат проверяется отдельно. |
| Входы/выходы | Вход — промт с манифестом навыков и безопасными публичными ссылками. Выход — отчёт + PR; агент обязан вернуть поля `sources_read`, `sources_unavailable`, `skills_read`, `skills_skipped`, `skills_unavailable`, точную GitHub-ссылочку (ref), готовый Markdown, противоречия и без непроверенных утверждений. |
| Разрешено | подготовка промта/пакета; только безопасные публичные ссылки; манифест навыков. |
| Запрещено | авто-выбор; приватные локальные пути; секреты, `.env`, токены; непубличное содержимое навыков. |
| Модель/инструмент | внешний GitHub-aware агент (управляется пользователем). |
| Переходы | Q (ручной) → X (автоматический аналог). |
| Останов/блокировка | обязательный навык недоступен — агент останавливается и сообщает блокер; контекст нельзя безопасно опубликовать — Q заблокирован для этой части. |
| Навыки | отдельного контрольного навыка у Q нет; источник истины — диспетчер `opencode-mcp-windows-control`; манифест перечисляет нужные навыки. |
| Real Wargame | исполнитель Q обязан следовать политике feature-веток проекта (правила проекта сильнее глобальных X-инструкций, см. раздел 6). |

Готовый ручной пакет для Q с промтом, манифестом и ссылками — в
`docs/ai/OPENCODE_ROUTES_EXTERNAL_Q.md`.

### 3.7 Маршрут R — ручной `/zworker` (пользовательский, ZIP)

| Поле | Значение |
|---|---|
| Назначение | Ручной внешний рабочий маршрут: пользователь сам работает с внешним чатом, результат — ZIP с `answer.md`. |
| Селектор | Только когда пользователь явно просит `/zworker` или внешний рабочий маршрут. |
| Триггеры | явный `/zworker`; пользователь хочет управлять внешним чатом вручную; автоматический браузерный маршрут заблокирован; вход/2FA/CAPTCHA блокируют автоматизацию; пользователю нужно загружать файлы вручную; нужна конкретная внешняя сессия/чат. |
| Рабочий процесс | Codex готовит prompt-pack (Request ID, ссылки на инструкцию и навигацию, ядро задачи, точные публичные HTTPS-ссылки, требование вернуть ZIP с `answer.md`); пользователь → внешний чат → ZIP с `answer.md`; Codex/OpenCode безопасно распаковывают во временную папку; первым читается `answer.md`; Codex решает следующий шаг. |
| Входы/выходы | вход — `prompt.md` (+ поддерживающие файлы); выход — ZIP с `answer.md` (+ файлы при необходимости). |
| Разрешено | короткий prompt-pack только с нужными элементами; точные публичные HTTPS-ссылки (лучше `raw.githubusercontent.com`); безопасная распаковка с отклонением опасных шаблонов (абсолютные пути, `..`, выход из временной папки, автозапуск). |
| Запрещено | служебные маркеры старого zchat (PACKAGE_READY, BLOCKED_MISSING_CONTEXT, CONTRACT_CONFLICT, manifest, checksums, payload, receive_pack, verify_pack и т.п.); относительные пути; Windows/Unix абсолютные пути; `file://` URI; UNC/SMB пути; публикация секретов и `.env`. |
| Модель/инструмент | внешний чат (управляется пользователем); OpenCode — для разведки репозитория и обработки ZIP. |
| Переходы | R (ручной) → W (автоматический ZIP-маршрут). |
| Останов/блокировка | если нужный контекст нельзя безопасно опубликовать — R заблокирован для этой части до перехода на A/C или изменения workflow. |
| Навыки | `opencode-zworker-control` — условный, подгружается только для `/zworker`. |
| Real Wargame | если потом применяются изменения из ZIP — сохранять «одна задача → одна ветка → один PR», без прямых записей в `main`. |

### 3.8 Маршрут W — автоматический R-подобный ZIP-маршрут

| Поле | Значение |
|---|---|
| Назначение | Автоматизированный аналог R: Codex сам выполняет внешний ChatGPT Web маршрут и получает ZIP с `answer.md`. |
| Селектор | когда репозиторий не отмечен как collaborative GitHub-разработка; X недоступен или неуместен; нужен результат в виде ZIP; внешний исполнитель работает с опубликованного raw/GitHub контекста. |
| Триггеры | выбор Route W / `zworker-auto` планировщиком; фаза высокого качества мышления при достаточном опубликованном GitHub-контексте. |
| Рабочий процесс | Route A разведка при необходимости → гарантировать, что нужный контекст доступен по публичным GitHub/raw URL (если локальное новее GitHub — опубликовать минимум на временной контекстной ветке `zworker-context/<request-id>`) → `opencode_zworker_auto_run` → ChatGPT Web → ZIP с `answer.md` → локальная передача (распаковка, чтение `answer.md` первым, обработка). |
| Входы/выходы | вход — промт с `Required Skills Manifest`; выход — ZIP с `answer.md`; в `answer.md` обязательны `skills_read`, `skills_skipped`, `skills_unavailable`. |
| Разрешено | автоматизация браузера через одобренный Chrome/Plus-профиль (headful, CDP attach); публикация минимального контекста на временной ветке; безопасная распаковка. |
| Запрещено | секреты и `.env`; локальные непубликуемые факты; быстрая проверка `git status`/инспекция; простое чтение/поиск файлов; выполнение тестов; установка зависимостей; server/watch команды; точечные правки в 1–3 строки; случаи, где веб-задержка не оправдана. |
| Модель/инструмент | ChatGPT Web через автоматизацию браузера (headful Chrome, CDP attach, известный Plus-профиль); инструмент `opencode_zworker_auto_run` из `mcp__opencode_jobs`. |
| Переходы | W → A локальная обработка результата → C тяжёлый ремонт при необходимости → A финальная проверка. |
| Останов/блокировка | если `opencode_zworker_auto_run` недоступен — остановиться и сообщить блокер, без молчаливого перехода на ручной скрипт без разрешения; если контекст нельзя безопасно опубликовать — W заблокирован. |
| Навыки | `zworker-auto` — читать перед использованием Route W. |
| Real Wargame | в collaborative-репозитории W не является сильным маршрутом по умолчанию: для сложной работы там X. |

### 3.9 Маршрут X — автоматический GitHub-aware маршрут ветка/PR

| Поле | Значение |
|---|---|
| Назначение | Автоматизированный аналог Q: Codex сам управляет сильным внешним web/chat исполнителем, который работает через GitHub и возвращает ветку + PR + отчёт + терминальный маркер. |
| Селектор | по умолчанию для сложной работы в collaborative GitHub-репозиториях; также явный `/X`. |
| Триггеры | несложная… нет, **сложная/средняя/архитектурная/многофайловая** работа в collaborative-репозитории; явный `/X` пользователя. |
| Рабочий процесс | одна ограниченная Route A разведка при необходимости → проверка CDP на `127.0.0.1:9223` → подключение/запуск известного Plus-профиля → подача промта → ожидание терминального блока (`BEGIN XROUTE-<id>` … `END XROUTE-<id>`) в последнем сообщении → одна OpenCode-опосредованная GitHub-верификация → отчёт. |
| Входы/выходы | вход — промт с `Required Skills Manifest` и безопасными публичными ссылками; выход — ветка + PR (или прямой push) + отчёт + терминальный маркер + результаты верификации. |
| Разрешено | доставка ветка/PR к целевому маршруту проекта (для Real Wargame — `real-wargame-preview`); верификация через OpenCode-опосредованный GitHub MCP; после верификации — синхронизация локальной preview-папки через Route A. |
| Запрещено | локальные непубликуемые факты; секреты и `.env`; быстрая инспекция/чтение; выполнение тестов; установка зависимостей; server/watch; точечные правки 1–3 строки; прямые записи в `main`; слияние без разрешения; auto-merge; запасные браузерные транспорты (например, `playwright.browser_tabs` как основной). |
| Модель/инструмент | ChatGPT Web через автоматизацию браузера (headful Chrome, CDP attach на `http://127.0.0.1:9223`, профиль `chrome-zworker-plus-next`); верификация — через OpenCode-опосредованный GitHub MCP. |
| Переходы | X → одна OpenCode GitHub-верификация → Route A синхронизация локальной preview-папки → отчёт. Q (ручной) → X (автоматический). |
| Останов/блокировка | требуется вход — `X_ROUTE_SESSION_EXPIRED_OR_REVOKED`, остановка без автоматизации паролей/2FA/CAPTCHA; антибот/Cloudflare — попросить пользователя разблокировать вручную; не тот профиль/аккаунт — остановка; сбой CDP attach — остановка; верификация не подтвердила доставку — маршрут не завершён; при расхождении отчёта и diff GitHub имеет приоритет. |
| Навыки | `x-route-control` — читать перед использованием Route X; `opencode-github-mcp-control` — читать перед любым GitHub-чтением/записью внутри X. |
| Real Wargame | цель доставки — `real-wargame-preview`; нацеливание на `main` — нарушение preview-политики, если нет явного `MAIN_GO_APPROVED_BY_USER`. Текущая политика проекта сильнее глобальной X-инструкции (см. раздел 6). |

#### Обновлённый транспорт Route X

Актуальная публичная копия навыка и скриптов находится в
`.agents/skills/route-public/x-route-control/` и перечислена в
`docs/ai/ROUTE_SKILLS_MANIFEST.md`. Для X обязательна последовательность:

```text
Run-X-Chrome.ps1 → Open-X-Auto-Chat.ps1 → Send-X-Route-Prompt.ps1
```

Рабочий транспорт — только выделенный видимый Chrome-профиль
`chrome-zworker-plus-next` с CDP `9223`. Встроенный браузер, `browser-client.mjs`,
`node_repl`, `agent.browsers`, расширение Chrome и `playwright.browser_tabs` не
являются транспортом X. После временного сбоя сначала повторяется штатная
проверка того же CDP через тот же скрипт; затем маршрут останавливается с точной
причиной, без выбора другого браузера.

Скрипты учитывают отрисовку интерфейса: пауза после готовности Chrome — `1000`
мс, после открытия/переключения страницы — `750` мс, после маркера ответа перед
поиском ссылки — `2000` мс, перед проверкой ссылки — `750` мс. Это не повторная
отправка запроса.

Если модель явно сообщает, что запись остановила система безопасности OpenAI до
выполнения записи, она добавляет сигнал
`<!-- X_ROUTE_RETRY: safety_write_block -->`. Скрипт только распознаёт этот
сигнал: ждёт `10` секунд, создаёт новый `request_id`, открывает новый чат и
делает ровно одну повторную попытку. Обычный `status: blocked`, отказ GitHub,
недостаток прав или предположение о причине повтор не запускают. После одной
повторной попытки дальнейшие повторы запрещены.

### 3.10 R-init (интеграция: Route X как транспорт для preview-цикла)

R-init preview-доставка использует Route X как транспортный слой: Route X работает
с постоянной веткой `real-wargame-preview`, прямой push/обновление preview по
умолчанию (без PR). Контрактом рабочего процесса владеет `r-init-control`
(preview-ветка, чеклист, GO/NO-GO, merge-handoff); Route X отвечает только за
доставку. R-init не переопределяет правила Route X и не дублирует транспортную
логику.

## 4. Ручные, автоматические, запасные и специализированные маршруты

### Ручные (управляются пользователем, Codex не выбирает автоматически)
- **R** — ручной `/zworker`: внешний чат, результат ZIP.
- **Q** — ручной GitHub-aware внешний запрос: результат ветка + PR.

Ручной/автоматический аналог:
```text
R (ручной /zworker, ZIP)  → W (автоматический ZIP)
Q (ручной GitHub-агент, PR) → X (автоматический PR)
```

### Автоматические (Codex выбирает по фазам)
- **A** — стандартный OpenCode/DeepSeek.
- **L** — узкий нативный микро-патч на готовом контексте.
- **W** — автоматический ZIP.
- **X** — автоматический ветка/PR.

### Запасные (fallback)
- **B** — запасной «колокол»: только после реального сбоя прямого маршрута в
  текущей задаче, только одна ограниченная попытка.
- Цепочка запасных моделей внутри A: `deepseek/deepseek-v4-flash` →
  `opencode/deepseek-v4-flash-free` → `opencode/mimo-v2.5-free`.

### Специализированные
- **C** — тяжёлая локальная работа через jobs/minimax.
- **D** — нативные модели Codex (только по явной просьбе) и прямой `comfyui-mcp`.
- **R-init** — Route X как транспорт для preview-цикла.
- **A-journal** — документальный подтип Route A для сессионных артефактов.

## 5. Цепочки маршрутов (диаграммы)

Типовая цепочка одной задачи (plain text):

```text
разведка/чтение контекста        → A
готовая ограниченная микро-правка → L  (только узкие действия на готовом контексте)
GitHub/контекст для Web           → GitHub control через OpenCode
сильное внешнее мышление         → X (GitHub, ветка + PR)
                                  → W (ZIP), если X недоступен или нужен ZIP
проверка результата               → A
тяжёлый локальный ремонт          → C  (при необходимости)
решение/итоговый отчёт            → Codex
```

Полная каноническая цепочка:

```text
Route A → Route L (только узкие действия на готовом ограниченном контексте)
        → GitHub sync (если Web нужен свежий опубликованный контекст)
        → Route X/Route W (сильное внешнее мышление)
        → Route A (проверка результата)
        → Route C (только если A не может закончить тяжёлый локальный ремонт)
        → решение Codex
```

Компактная схема переходов:

```text
A → L → X/W → A → C
R → W
Q → X
B → A (временный аварийный возврат)
```

Цепочка сбоя и восстановления:

```text
прямой mcp__opencode.* сбой в текущей задаче
  → один ограниченный B (mcp__opencode_jobs.opencode_job_run_and_wait)
  → следующая новая задача снова со стандартного mcp__opencode.*
```

Цепочки специальных маршрутов:

```text
ComfyUI MCP                    → D (всегда, автоматически; A запрещён для этого MCP)
Нативные модели Codex          → D (только по явной просьбе пользователя)
R-init preview-цикл            → r-init-control (workflow) + Route X (транспорт)
```

## 6. Приоритет источников: глобальная X-инструкция против политики Real Wargame

### Приоритет источников (от высшего к низшему)

1. Проектные канонические источники Real Wargame: `AGENTS.md`,
   `docs/ai/repo-context.json`, `docs/ai/WEB_CHAT_START.md`,
   `docs/ai/TASK_ROUTER.md`, `docs/workflow/WEB_CHAT_FEATURE_DELIVERY.md`,
   `docs/workflow/EXTERNAL_CHAT_REQUIRED_RULES.md`,
   `docs/workflow/SKILL_PATCH_PREVIEW_BRANCH_POLICY.md`.
2. Локальные маршрутные источники окружения: диспетчер
   `opencode-mcp-windows-control` и напоминание `routing-reminder`
   (локальные, не публичные, см. раздел 9).
3. Глобальные X/Q-инструкции внутри локальных маршрутных навыков.

### Конфликт глобальной X-инструкции и текущей политики проекта

Глобальное напоминание `routing-reminder` (раздел «Permanent preview formula»)
говорит, что для Real Wargame внешние GitHub-aware чаты должны по умолчанию
коммитить/пушить готовые изменения **напрямую в `real-wargame-preview`**, а PR —
запасной путь.

Текущая политика Real Wargame (AGENTS.md и канонические workflow) говорит
обратное:

- реализация выполняется на временной feature-ветке
  `feature/YYYYMMDD-short-kebab-slug` от точного HEAD `real-wargame-preview`;
- **никакой прямой разработки в preview**; `real-wargame-preview` — цель
  приёмки, а не ветка разработки;
- **никаких записей в `main`** без отдельного явного GO пользователя;
- PR — не маршрут по умолчанию;
- `docs/workflow/SKILL_PATCH_PREVIEW_BRANCH_POLICY.md` явно отменяет старое
  правило «пушить готовую работу напрямую в real-wargame-preview».

Разрешение конфликта: **выигрывают проектные AGENTS.md и канонические
workflow.** Глобальная X-инструкция «прямой push в preview» не отменяет контракт
проекта. Это же правило применяется к исполнителям Q и X: доставка идёт на
feature-ветку и переносится в preview только после явного GO пользователя.

## 7. Что НЕ относится к этим маршрутам

### Игровые «маршруты» Real Wargame не связаны с маршрутами Codex/OpenCode

В Real Wargame слово «route» также используется в игровом смысле: пути движения
юнитов, навигация, pathfinding, стоимость маршрутов, реактивный статус маршрута.
Примеры документов: `GRID_PATHFINDING_V1.md`, `ROUTE_COST_OVERLAY_V1.md`,
`TACTICAL_ROUTE_COST_V1.md`, `REACTIVE_ROUTE_STATUS_V1.md`, `PLAYER_COMMAND_PLAN_ROUTE_OVERLAY_V1.md`.

Это игровые/навигационные концепции и **не имеют отношения** к маршрутам
выполнения задач Codex/OpenCode A/B/C/D/L/Q/R/W/X, описанным в этом документе.
Не путайте их: один набор выбирает, как агент выполнит задачу, второй —
как юнит в игре пойдёт из точки в точку.

### `@Superpowers` — процессный навык, не маршрут D

`@Superpowers` — процессный навык (метод ведения работы). Его подключение не
означает выбор Route D и не заменяет явную просьбу пользователя про нативные
модели Codex. Route D выбирается только по явной просьбе (или автоматически для
`comfyui-mcp`).

## 8. Наблюдаемые риски окружения

- **2026-08-21, job-wrapper и minimax-m2.5.** Обёртка задач
  (`opencode_job_run_and_wait`) при попытке задействовать Route B/C обратилась к
  выведенной из эксплуатации модели `minimax-m2.5`. Это **наблюдение окружения**,
  а не придуманное универсальное правило: документируйте такие факты как
  «observed environment risk» и не выдавайте их за общий закон. Правило действий
  остаётся прежним: недоступность/непригодность провайдера или модели — остановка
  и объяснение блокера, без молчаливой подмены маршрута.
- Прямые GitHub-инструменты Codex запрещены всегда, даже для чтения; GitHub-работа
  выполняется только через OpenCode-опосредованный маршрут. Нарушение — ошибка
  маршрута, даже если результат корректен.
