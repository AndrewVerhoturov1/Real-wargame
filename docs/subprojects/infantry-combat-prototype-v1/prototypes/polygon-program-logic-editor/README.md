# Полигон — прототип редактора действий и логики программы v8.2

## Статус

Это принятый UX-прототип редактора программы Полигона. Он фиксирует согласованную структуру интерфейса, каталог действий, параметры шагов, логические конструкции и визуальную схему дорожек.

Прототип **не является production-реализацией** и не должен использоваться как источник игровой истины. При переносе решений в приложение приоритет имеют актуальные реестры, контракты Graph v2 и runtime-код репозитория.

## Состав каталога

- [`polygon-program-logic-editor-v8.2.html`](./polygon-program-logic-editor-v8.2.html) — локальный файл запуска.
- [`payload-manifest.json`](./payload-manifest.json) — формат пакета, список частей и контрольные суммы.
- `payload/part-01.js` … `payload/part-14.js` — сжатый payload принятого HTML.
- `README.md` — назначение, возможности, ограничения и инструкция по запуску.

## Формат хранения в репозитории

Исходный автономный HTML имеет размер около 590 КБ. В репозитории он хранится как точный локальный пакет:

1. исходный HTML сжат в gzip;
2. бинарные данные закодированы Base64;
3. строка разделена на 14 небольших локальных JavaScript-файлов;
4. файл запуска объединяет части, распаковывает их через `DecompressionStream('gzip')` и открывает восстановленный HTML.

Файл запуска и payload не обращаются к сети. Восстановленное содержимое байт-в-байт совпадает с принятой автономной версией.

Контрольные суммы:

```text
Исходный HTML SHA-256:
71bee9ec9a6719931d4c46e8b1b939ca6fa95ea24a2d5fda9887c1a344c6889e

Gzip payload SHA-256:
cbb0d7c9191162b6e7c2b0f1236fd6d7812f2993773fb44952a55f7262ce38c0
```

## Как запустить

Нужно скачать или клонировать **весь каталог** `polygon-program-logic-editor`, сохранив подпапку `payload` рядом с HTML-файлом.

Структура должна остаться такой:

```text
polygon-program-logic-editor/
├── polygon-program-logic-editor-v8.2.html
├── payload-manifest.json
├── README.md
└── payload/
    ├── part-01.js
    ├── ...
    └── part-14.js
```

После этого откройте `polygon-program-logic-editor-v8.2.html` напрямую в современном Chromium-браузере: Chrome, Edge или Яндекс Браузере.

Пример локального адреса:

```text
file:///C:/Users/<user>/Downloads/polygon-program-logic-editor/polygon-program-logic-editor-v8.2.html
```

Сервер, сборка, npm и подключение к интернету не требуются. Отдельный HTML без каталога `payload` не загрузится.

## Назначение

Прототип показывает целевую UX-модель следующих частей Полигона:

- создание и редактирование программ эксперимента;
- дорожки исполнителей и последовательности шагов;
- сокращённый каталог базовых действий;
- редактор параметров каждого действия;
- условия, ветвления, циклы и параллельные ветви;
- схема отдельной дорожки и общая схема программы;
- связь параметров с существующими игровыми редакторами и нодами Graph v2;
- явное обозначение возможностей, которых пока нет в игре.

## Основные принципы

### Одно действие — одно намерение

Похожие команды не размножаются отдельными пунктами каталога. Различия задаются параметрами действия.

Например, обычное движение, скрытное движение, бег и движение пригнувшись представлены одним действием «Перемещение», а конкретное поведение выбирается через реальный профиль движения и профиль маршрута.

### У каждого параметра есть источник

Параметр относится к одному из четырёх типов:

1. **Graph v2** — точный параметр или поведение существующей ноды.
2. **Игровой редактор** — ссылка на реальный профиль или запись реестра.
3. **Полигон** — собственная настройка программы эксперимента.
4. **Заглушка** — видимая возможность, для которой в игре ещё нет механики.

Блок «На чём основано действие» находится внизу редактора шага и по умолчанию свёрнут.

### Реальные названия редакторов

Прототип использует структуру существующей платформы игровых редакторов:

- Граф поведения;
- Профили маршрута;
- Тактические позиции;
- Данные бойца;
- Архетипы бойцов;
- Профили внимания;
- Профили восприятия;
- Профили движения;
- Вооружение;
- Ранения и подавление;
- Профили местности;
- Направленный рельеф.

В прототип встроен снимок известных на момент создания версии 8.2 встроенных значений. Пользовательские профили, созданные в другом браузере или другой сборке приложения, автоматически в пакет не попадают.

## Каталог действий

Каталог сокращён до 59 базовых действий. Варианты одного намерения вынесены в параметры и вкладки.

Основные группы:

- перемещение;
- наблюдение и контакты;
- стрельба;
- оружие и боеприпасы;
- взаимодействие;
- медицинские действия;
- связь и командование;
- групповые действия;
- транспорт и поддержка;
- пленные;
- управление программой.

## Редактор действия

Каждое действие открывается в общей оболочке:

- заголовок и статус;
- вкладки параметров;
- основная настройка;
- маршрут, оружие, реакции, неудача и дополнительные поля — когда применимо;
- кнопки сохранения, копирования и удаления;
- сворачиваемый блок источников.

Источники и реальные значения применяются не только во вкладке «Основное», а во всех связанных вкладках.

## Управление программой

Прототип содержит отдельные рабочие модели для:

- ожидания времени, условия, сигнала, шага или ветви;
- условия и ветвления;
- параллельного запуска;
- ожидания параллельных ветвей;
- цикла;
- отправки и ожидания программного сигнала;
- перехода к шагу или контрольной отметке;
- пропуска шагов;
- завершения дорожки;
- завершения эксперимента;
- контрольной отметки;
- лабораторного изменения состояния.

Ссылки на шаги, ветви и выходы строятся по фактической структуре программы, а не по демонстрационным строкам.

## Конструктор условий

Условия собираются без ручного кода.

Поддерживаются:

- группа `И`;
- группа `ИЛИ`;
- оператор `НЕ`;
- вложенные группы;
- перенос условий между группами;
- выбор группы как текущей цели добавления;
- запрет вложения группы в саму себя или собственного потомка;
- строго один дочерний элемент у `НЕ`.

Специализированный конструктор встроен в общую оболочку редактора действия и сохраняет вкладки, кнопки и блок источников.

## Схема программы

В версии v8.2:

- ветвление и параллельный запуск показаны компактными нодами-маршрутизаторами;
- высота логической ноды зависит от числа выходов;
- подпись каждого выхода находится напротив своего порта;
- главная параллельная ветвь помечается отдельно;
- порты имеют неподвижную область захвата;
- наведение не смещает фактический центр порта;
- линии строятся по реальным центрам DOM-портов;
- связи используют ортогональные маршруты со скруглёнными углами;
- обратные связи обходят ноды сверху или снизу без больших самопроизвольных петель;
- доступны ручные точки изгиба.

## Использованные реальные данные

Прототип содержит снимки встроенных данных и схем, включая:

- профили движения;
- профили маршрута;
- профили внимания;
- профиль тактической позиции;
- профили восприятия, архетипы и условия бойца;
- материалы местности;
- классы оружия и режимы огня;
- встроенные боеприпасы, оружие и комплекты снаряжения;
- типы и параметры нод Graph v2.

Например, доступные режимы огня зависят от выбранной реальной записи оружия: винтовка Мосина допускает одиночный огонь, а ППШ-41 и ДП-27 — режимы, предусмотренные их каталогом.

## Заглушки

Если параметр нужен для целевого UX, но соответствующей механики нет в текущей игре, он не маскируется под рабочий.

Такие элементы:

- имеют отдельное визуальное оформление;
- подписаны как отсутствующая механика;
- не выдаются за параметр существующей ноды или редактора.

## Ограничения

- Репозиторная копия представляет собой локальный статический пакет, а не модуль Vite/TypeScript-приложения.
- Прототип не запускает настоящую симуляцию и не изменяет production-реестры.
- Встроенные игровые данные являются снимком на момент создания версии 8.2.
- Пользовательские профили из `localStorage` основной игры автоматически не синхронизируются.
- Часть действий демонстрирует целевую модель авторинга, а не готовый runtime-контракт.
- Прототип нельзя переносить в production копированием целиком; решения должны быть реализованы через существующие типы и реестры проекта.
- Для запуска репозиторной копии требуется Chromium с поддержкой `DecompressionStream`.

## Правило дальнейшего использования

Прототип следует использовать как согласованный визуальный и функциональный ориентир при проектировании production-редактора. При расхождении прототипа с актуальными контрактами репозитория приоритет всегда имеет production-код и его авторитетные реестры.
