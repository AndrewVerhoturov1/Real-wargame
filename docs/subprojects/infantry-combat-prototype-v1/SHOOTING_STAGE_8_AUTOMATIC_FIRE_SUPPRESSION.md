# Stage 8 — автоматический огонь и физическое подавление

## Граница этапа

Stage 8 расширяет принятую систему одиночного выстрела до коротких и длинных очередей ППШ, а также до ограниченного огня по области. Каждый патрон остаётся отдельным физическим выстрелом и отдельной пулей.

Этап не добавляет готовое поведение Graph v2, автоматическую реакцию на подавление, пулемёт, установку оружия, помощника, интерфейс или развёртывание.

## Используемые опубликованные данные

Новые ревизии каталогов не создавались. Используются существующие опубликованные определения:

- `weapon_ppsh41@1`;
- `ammo_762x25_tokarev@1`;
- `loadout_submachine_gunner@1`.

ППШ предоставляет режимы `single`, `short_burst`, `long_burst`, `suppress`, темп `900 выстрелов/мин`, короткую очередь `4` патрона и длинную очередь `10` патронов.

## FireTask V2

Сохраняемая огневая задача хранит:

- режим;
- точку и радиус области;
- запланированное число выстрелов;
- следующий порядковый номер;
- следующую разрешённую границу выстрела;
- время начала очереди и последнего выстрела;
- ограниченный список уже зафиксированных выстрелов;
- номер и последнюю опорную точку огня по области;
- обычные фазы подготовки, прицеливания, стрельбы и восстановления.

Старая задача V1 мигрирует как одиночный выстрел с одним запланированным патроном. Уже сохранённый `committedShotId` становится записью порядкового номера `0`.

## Темп оружия

Экземпляр оружия V2 хранит:

- `nextShotAllowedSeconds`;
- `lastCommittedShotSeconds`;
- `continuousFireScore`;
- последовательность непрерывного огня.

Интервал определяется только опубликованным темпом:

```text
shotIntervalSeconds = 60 / roundsPerMinute
```

Граница темпа принадлежит экземпляру оружия, поэтому отмена задачи или создание новой задачи не позволяет выстрелить раньше. Состояние сохраняется и восстанавливается.

## Атомарность каждого патрона

Каждый порядковый номер очереди проходит обычный `commitShot`:

```text
1 ordinal
→ 1 ammo consumption
→ 1 stable shotId
→ 1 projectileId
→ не более 1 physical projectile
→ 1 recoil impulse
```

До первой мутации формируется полный кандидат: направление, разброс, отдача, положение ствола, риск союзникам, пуля, запись журнала и следующее состояние темпа. При отказе патрон, отдача, темп и FireTask не меняются.

## Отдача и прицеливание

Между выстрелами продолжает работать принятая система Stage 5:

- решение прицеливания обновляется на границах `5 Гц`;
- физическое качество прицеливания развивается во времени;
- каждый выстрел получает текущее накопленное смещение отдачи;
- после успешного выстрела добавляется новый импульс;
- восстановление отдачи зависит от позы, движения, навыка, усталости и ранений.

Огонь во время движения разрешается или запрещается данными оружия. ППШ использует существующий разрешённый режим и множитель рассеивания.

## Огонь по области

Для `suppress` центр и радиус задаются в FireTask. Конечное число опорных точек рассчитывается чистой детерминированной функцией:

- радиальная доля использует равномерное распределение по площади круга;
- угол использует золотой угол;
- вся последовательность поворачивается устойчивым хешем `taskId`;
- все точки остаются внутри заданной области;
- после вылета пуля больше не корректируется.

## Физические события подавления

Подавление возникает только из подтверждённой физической траектории:

- `near_miss` — расстояние от пройденного отрезка пули до крупной геометрии бойца не больше `3 м`;
- `near_impact` — расстояние от фактической точки удара до бойца не больше `6 м`;
- `direct_hit` — физическое попадание в тело.

Цель прямого попадания не получает дополнительно событие близкого пролёта или близкого удара той же пули. Для каждого события сохраняются устойчивый ID, источник, затронутый боец, пуля, время, расстояние, входящее направление, базовый импульс и снимок непрерывности огня.

Непрерывный огонь только усиливает уже подтверждённые физические события. Он не создаёт подавление сам по себе.

## Окна подавления

Состояние бойца обновляется на глобальных полуоткрытых окнах `0,2 с`:

```text
[0,0; 0,2)
[0,2; 0,4)
...
```

Событие ровно на границе относится к новому окну. Внутри окна события агрегируются по `sourceUnitId`. На границе применяются:

- уровень подавления;
- краткий шок;
- непрерывность огня;
- доминирующее направление;
- ближайшая недавняя дистанция;
- оценка числа источников.

После этого состояние детерминированно затухает по времени симуляции. Подавление не меняет позу, маршрут, стрельбу или выбор поведения: это только физический факт для будущего Graph v2.

## Сохранение и восстановление

Снимок включает:

- частично выполненную очередь;
- каждый уже зафиксированный порядковый номер;
- темп и непрерывность экземпляра оружия;
- активные пули с их снимком непрерывности огня;
- незавершённое окно подавления;
- применённые ID событий;
- текущее затухающее состояние.

Reconciliation проверяет каждый committed-выстрел отдельно. Отсутствующая committed-пуля не создаётся повторно. Незавершённая очередь продолжает ожидать сохранённую границу темпа; полностью выполненная или исчерпавшая боезапас переходит в восстановление. Повторный reconciliation не меняет результат.

## Ограничения производительности

- вместимость пула пуль: `4096`;
- изменение размера пула запрещено;
- отдельный массив `Float64Array` хранит снимок непрерывности огня;
- буфер событий подавления: `4096 × 8 = 32768` записей;
- не более `8` событий подавления от одной пули за один подшаг;
- не более `32` ближайших кандидатов рассматривается для одного физического события;
- не более `16` агрегированных источников в окне одного бойца;
- не более `256` применённых ID событий на бойца;
- используются существующие `CombatUnitSpatialIndex` и `MapObjectSpatialIndex`;
- отдельный spatial index не создаётся;
- полного перебора всех бойцов на пулю нет;
- источники истины не хранятся в `WeakMap`;
- рабочие буферы выделяются один раз на runtime.

## Сложность горячего пути

Для одного фиксированного шага:

```text
O(projectile pool capacity)
+ O(local spatial candidates)
+ O(bounded suppression events)
```

В пуле выполняется линейный проход по фиксированной ёмкости `4096`, как в принятом Stage 4. Для каждой активной пули проверяются только кандидаты пересечённых пространственных корзин. Формы `projectile × all units` и полный проход карты отсутствуют.

## Проверки

Основные команды:

```text
npm run infantry-combat-stage8:smoke
npm run infantry-combat-stage8:forbidden-scan
npm run infantry-combat-stage8:verify
```

Smoke включает миграцию FireTask V1→V2, режимы ППШ, точный темп, совместимость одиночного выстрела, непрерывность темпа между задачами, распределение опорных точек, окна подавления, физические пролёты/удары/попадания, сохранение частичной очереди и нагрузочный прогон с `4096` активными пулями.
