# Отображение солдат видом сверху

## Goal

Зафиксировать и развивать принятую систему читаемых тактических знаков пехоты для 2D-карты: поза, направление, оружие, действия, состояния, роли и уровни детализации по масштабу.

Каноническое описание визуальной системы: `docs/subprojects/soldier-topdown-appearance/UNIT_SYMBOL_SYSTEM.md`.

## Current focus

Принята и зафиксирована базовая система отображения:

- стоящий боец — круг;
- присевший / движущийся пригнувшись — аккуратный симметричный скруглённый треугольник вершиной вперёд;
- лежащий — вытянутый прямоугольник с небольшим скруглением;
- направление корпуса — точка внутри знака у переднего края;
- оружие — отдельный знак, закреплённый основанием внутри тела справа у условного плеча;
- подавление — четыре отдельные скруглённые угловые скобки;
- ранение — круглый медицинский значок;
- смерть — серое полупрозрачное лежащее тело с небольшим крестом;
- командир — обычный знак бойца со звездой;
- три уровня детализации по масштабу;
- на дальнем масштабе обычный боец — точка, ДП — квадрат, командир — звезда, отделение — штрихованная область.

## Key decisions

- Визуальный язык пехоты **утверждён пользователем 2026-08-10**.
- Боец является простым тактическим знаком, а не человеческой фигуркой.
- Оружие визуально принадлежит бойцу: его основание всегда остаётся внутри основного знака справа, примерно у условного правого плеча; при действиях меняется угол оружия.
- Направление корпуса и направление оружия могут различаться.
- Информация последовательно упрощается при отдалении камеры, а не просто уменьшается физически.
- Убитые должны оставаться различимыми на всех уровнях масштаба.
- Система должна работать на настоящих данных редактора и карты. Отдельная демонстрационная сцена в конечной реализации не нужна.
- Рендерер показывает состояние игры и не является источником игровой истины.

## Boundaries

- Не менять принятый базовый визуальный язык без отдельного явного решения пользователя.
- Не переносить изменения в `real-wargame-preview` без отдельного GO.
- Не менять `main` без отдельного разрешения.
- Не затрагивать несвязанные изменения рабочего дерева.
- Визуализация не должна становиться источником игровой логики.

## Testing

Для документационных изменений используются:

- `npm run docs:sync`;
- `python scripts/subproject_context.py soldier-topdown-appearance --brief`.

При реализации в штатном рендере нужны отдельные программные и визуальные проверки соответствия `UNIT_SYMBOL_SYSTEM.md`.
