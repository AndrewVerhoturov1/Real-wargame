# Поэлементный перенос Полигона — канонический процесс

Статус: текущий принятый подход пользователя.
Дата фиксации: 2026-08-17.

## 1. Принцип

Полигон переносится из утверждённого HTML-прототипа в продукт **по одному элементу/вертикальному срезу**: вкладка, карта или другой конкретный элемент. Весь функциональный объём HTML-прототипа, включая запланированные возможности, остаётся целью подпроекта.

## 2. Два параллельных исполнителя на каждый элемент

1. **Визуальный** — переносит вёрстку, графику, отступы, цвета, размеры, шрифты и иконки из утверждённого HTML-прототипа пиксель в пиксель; функциональные связи пока не подключает.
2. **Аналитик** — сравнивает прототип и продукт и определяет:
   - что уже есть;
   - что частично есть;
   - чего нет;
   - настоящих владельцев данных;
   - точки подключения;
   - назначение каждой кнопки.

## 3. Затем отдельные исполнители

- подключающий уже готовые функции;
- доделывающий отсутствующие/неполные возможности;
- реализующий новые запланированные функции прототипа;
- при необходимости дополнительных исполнителей может быть несколько.

## 4. Критерии перехода элемента

Элемент считается готовым к интеграции только при выполнении всех условий:

- визуальный результат проверен против HTML;
- аналитическая карта функций/владельцев закончена;
- готовые функции подключены через настоящих владельцев данных;
- пробелы классифицированы;
- новые функции имеют отдельный объём и критерии приёмки;
- результат не содержит дублирующего состояния и не меняет соседние элементы без договора.

## 5. Отношение к прежней работе

Результаты прежней six-X волны сохраняются как исторические исследования и технический контекст. Они **не являются автоматическим основанием** для объединения кода.

Текущий checkpoint — техническая база, но **визуально не принят**.

## 6. Запреты

Без отдельного явного разрешения пользователя запрещены:

- автоматический перенос в `real-wargame-preview`;
- изменения `main`;
- merge;
- deploy.
