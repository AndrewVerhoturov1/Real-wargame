## Назначение

`Серия` — инструмент фонового многократного прогона одного настроенного эксперимента для накопления статистики и поиска закономерностей.

Основной цикл:

`один настроенный эксперимент → много независимых прогонов → накопление результатов → статистический анализ → выбор интересного прогона → воспроизведение его в обычном Полигоне`.

Режим рассчитан не на наблюдение одного боя в реальном времени, а на сотни, тысячи и при необходимости больше повторений одного эксперимента.

## Снимок эксперимента и воспроизводимость

При запуске Серии фиксируется снимок исходного эксперимента. Каждый прогон получает отдельное зерно (`seed`), поэтому независимые запуски отличаются друг от друга.

Интересный прогон воспроизводится не на текущем изменённом эксперименте, а на замороженном снимке Серии с его исходным seed.

Для production-воспроизводимости одного seed недостаточно: должны также сохраняться версия/идентичность simulation runtime и всё исходное состояние, влияющее на результат. Standalone-прототип фиксирует UX-контракт; production serialization и deterministic replay являются отдельной runtime-задачей.

## Основные состояния интерфейса

Вкладка использует одно рабочее пространство с тремя естественными состояниями:

1. `Настройка`;
2. `Выполнение`;
3. `Отчёт`.

Отдельные технические настройки потоков, workers и пакетирования в основной пользовательский интерфейс не выносятся.

## Настройка Серии

До запуска пользователь видит краткую идентификацию текущего эксперимента и задаёт количество прогонов.

Приняты быстрые значения количества прогонов и возможность ввести своё число. Для каждого прогона автоматически используется отдельное случайное зерно; все seed сохраняются для последующего воспроизведения.

Главное действие — `Запустить серию`.

## Выполнение

Во время расчёта показываются:

- общее количество прогонов;
- выполнено / осталось;
- полоса и процент прогресса;
- ошибки;
- скорость выполнения;
- действия паузы и остановки.

Статистика может формироваться до завершения всей Серии. Предварительные агрегаты уточняются по мере поступления новых результатов.

## Отчёт и связь с Метриками

Серия не создаёт параллельный каталог измерений. Она использует выбранные Метрики и анализирует их значения по множеству прогонов.

Для подходящей числовой метрики отчёт может показывать:

- среднее;
- медиану;
- минимум и максимум;
- диапазон/разброс;
- распределение значений;
- количество прогонов, попавших в конкретное значение или диапазон.

Графики распределения являются интерактивным способом отбора реальных прогонов, а не только иллюстрацией. Нажатие на значение или диапазон должно позволять перейти к соответствующим запускам.

## Все прогоны и фильтрация

Каждый прогон является отдельной сущностью с идентификатором, seed, результатом и значениями выбранных метрик.

Большой отчёт предоставляет список прогонов и фильтры по измеряемым параметрам. Условия отбора строятся на тех же сущностях Метрик, например:

- попадания конкретного юнита меньше заданного значения;
- потери стороны больше заданного порога;
- длительность боя входит в интересующий диапазон.

Отобранный прогон открывает подробности и может быть воспроизведён.

## Необычные прогоны

Необычные результаты являются одним из основных сценариев Серии.

Система может отмечать прогоны, заметно отличающиеся от большинства, без попытки автоматически объяснить причину. Пример: `0 попаданий`, когда почти все остальные прогоны содержат попадания.

Принято два уровня доступа:

- короткий блок необычных прогонов в общем обзоре Серии;
- отдельный полноценный раздел `Необычные` в большом отчёте.

Для необычного прогона показываются:

- номер прогона;
- причина выделения;
- фактическое значение;
- сравнение со статистикой всей Серии;
- seed;
- подробности выбранных метрик;
- действие `Воспроизвести прогон`.

Пользователь должен иметь возможность открыть полный список необычных прогонов, а не только несколько примеров.

Принятый исправленный сценарий v1.1:

`обзор/большой отчёт → необычный прогон → его контекст отклонения → карточка → seed → воспроизведение → возврат к тому же прогону в отчёте`.

## Воспроизведение отдельного прогона

Кнопка `Воспроизвести прогон` переводит пользователя из статистического режима в обычный живой Полигон.

В режиме воспроизведения показывается контекст Серии, номер прогона и seed, а также действие возврата к отчёту. Сам бой не воспроизводится внутри интерфейса Серии: Серия отвечает за массовый анализ, обычный Полигон — за наблюдение конкретного боя.

Если исходный снимок, версия simulation runtime и seed совпадают, production-реализация должна стремиться к детерминированному воспроизведению того же результата.

## История Серий

Завершённые Серии являются результатами исследования и должны сохраняться. Пользователь может открыть предыдущую Серию и продолжить анализ её агрегатов и отдельных прогонов.

## Границы с другими разделами

Роли разделены так:

- `Лаборатория` — какие временные изменения проверяются;
- `Метрики` — что именно измеряется;
- `Серия` — что происходит при многократном повторении одного эксперимента;
- `Журнал` — что конкретно происходило во времени в одном прогоне.

Series v1 — standalone UX/reference-прототип. Он не доказывает наличие production background runner, хранилища результатов, telemetry aggregation или deterministic replay.

## Отложено за пределы v1

В первую принятую версию сознательно не включены как обязательные функции:

- сравнение двух Серий;
- объединение нескольких Серий;
- сложные статистические тесты;
- ручное управление worker-потоками;
- ручное управление распределением seed;
- научный экспорт отчётов;
- автоматические ИИ-выводы о причинах результата.

## Следующие runtime-задачи

- production background runner для сотен/тысяч независимых прогонов;
- сохранение замороженного experiment definition;
- генерация и хранение seed каждого прогона;
- фиксация версии simulation runtime для воспроизводимости;
- production telemetry aggregation поверх выбранных Метрик;
- хранилище Серий и результатов отдельных прогонов;
- deterministic replay конкретного запуска;
- производительность, отмена, пауза и восстановление долгих Серий.

Деплой этой приёмкой не выполнялся.
