## Назначение

Лаборатория задаёт временные экспериментальные overrides: `параметр + экспериментальное значение + цель/область действия`. Она не заменяет обычные глобальные игровые настройки и не становится отдельным production source of truth.

Роли разделены так: Редактор юнита — участники и стартовое состояние; Редактор карты — пространство; Программа — последовательность; Лаборатория — временные переопределения; Метрики — сбор данных; Журнал — разбор факта; Общие редакторы — обычные игровые значения.

## Граница UI

Лаборатория использует только левую рабочую панель, popup-конструктор, контекстное меню и интерактивный слой центральной карты. Верхняя шапка и правая панель не меняются.

В левой панели приняты подвкладки `Изменения` и `Области`. Набор кнопок инструментов зависит от активной подвкладки и текущего объекта, по принципу редактора карты.

## Выбор и области

- один инструмент выбора работает и для одного, и для нескольких юнитов;
- рамка предназначена только для массового выбора юнитов;
- полигональная область создаётся отдельным инструментом;
- область является переиспользуемым объектом и может применяться к нескольким overrides;
- вершины области редактируются непосредственно на карте;
- геометрия хранится в координатах карты, поэтому zoom/pan не сдвигают её относительно местности.

Клик по изменению открывает подробности в той же левой панели и подсвечивает точную цель на карте. Полный конструктор открывается действием `Изменить`.

## Контекстное меню

Контекстное меню зависит от юнита, группы, пустой карты, области и редактируемой вершины. Важный сценарий — `Действующие изменения` для выбранного юнита: пользователь может увидеть применимые личные, групповые и областные overrides и открыть их в Лаборатории.

## Конструктор

Принят компактный трёхколоночный паттерн по образцу конструктора Метрик:

1. категории слева;
2. каталог параметров по центру;
3. редактор выбранного параметра справа.

Отдельных шагов `Параметр / Цель / Значение` нет. Правая колонка компактная и содержит текущее значение, экспериментальное значение, цель, источник и специфические настройки выбранного параметра.

Каталог и редактор имеют независимую прокрутку. Локальные клики и изменения полей не должны возвращать список наверх.

Для всех числовых параметров используются синхронизированные slider + numeric input. Для boolean, enum и других типов используются соответствующие типу контролы.

## Источники параметров и runtime boundary

Лаборатория не должна поддерживать второй вручную скопированный каталог параметров. Standalone UX использует существующие схемы/registry definitions Полигона; production-реализация должна строиться через descriptor/adapter layer над настоящими владельцами параметров.

`Применить глобально` допустимо только когда у параметра существует однозначный постоянный authoritative owner. Для чистого runtime state это действие не применяется.

Laboratory v1 — standalone UX/reference-прототип. Production simulation и registry/config sources остаются authoritative; production resolution chain лабораторных overrides является отдельной задачей.
