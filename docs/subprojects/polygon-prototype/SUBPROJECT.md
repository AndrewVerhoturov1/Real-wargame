# Полигон — редактор эксперимента

## Назначение

«Полигон» — подпроект Real Wargame для подготовки и проведения воспроизводимых тактических экспериментов. Центральная карта остаётся общим рабочим пространством, вокруг которого собраны редакторы карты, участников, программы, запуска и анализа результатов.

Автономные HTML-прототипы используются как UX/reference-контракты до production-подключения. Они не заменяют игровые модели, реестры и simulation runtime.

## Что уже принято

### Редактор юнита

Рабочий UX-прототип создания и настройки участника: выбор, перемещение, поворот, позы, архетипы, профили, стартовое состояние и тактический знак.

### Отображение пехоты

Пехота отображается условными знаками: круг — стоя, скруглённый треугольник — на корточках, вытянутый прямоугольник — лёжа. Сохраняются отдельное направление корпуса и оружия, тип оружия, действие, состояния и уровни детализации.

### Редактор карты

Принят авторинг поля, рельефа, поверхностей, растительности, линейных объектов, зданий и предметов, а также история действий, запекание и сохранение/загрузка результата.

### Программа

Принят редактор программы эксперимента: дорожки, шаги, действия, условия, ветвления, циклы, параллельные ветви и привязки к карте/участникам.

### Метрики v18

Принят UX полного цикла настройки измерений и последующего анализа. Measurement definition определяет поток исходных данных, а Отчёт выполняет постфактум-анализ, не меняя raw telemetry. Production telemetry wiring остаётся отдельной задачей.

Подробный контракт: `ACCEPTED_METRICS_V18.md`.

### Журнал v4

Принят read-only UX причинно-временного разбора эксперимента: единая лента, фильтры, inline-подробности, глобальная хронология, LIVE/HISTORY навигация и исторический unit inspector. Production replay/history provider остаётся отдельной задачей.

Любые субъективные данные в историческом режиме обязаны использовать выбранный `viewTime`: будущие контакты, знания, состояния оружия и причины не должны просачиваться назад по времени.

Подробный контракт: `ACCEPTED_JOURNAL_V4.md`.

### Общие редакторы v1

Принят единый popup/workbench из шапки Полигона с постоянной левой навигацией, списком сущностей/профилей и большой рабочей областью.

Состав:

**Поведение**
- `Профили маршрута`;
- `Тактические позиции`.

**Боец**
- `Архетипы бойцов`;
- `Профили внимания`;
- `Профили восприятия`;
- `Профили движения`.

**Бой**
- `Вооружение`;
- `Ранения и подавление`.

**Мир**
- `Типы поверхностей`;
- `Профили местности`;
- `Направленный рельеф`.

`Граф поведения` и `Данные бойца` по продуктовому решению не входят в это меню. Standalone authoring может разрешать редактирование gameplay tuning, но это не означает production wiring.

Подробный контракт: `ACCEPTED_GLOBAL_EDITORS_V1.md`.

### Лаборатория v1

Принят раздел временных экспериментальных overrides. Основная сущность:

`параметр + экспериментальное значение + цель/область действия`.

Ключевые решения:

- Лаборатория живёт в левой рабочей вкладке, popup-конструкторе, контекстном меню и интерактивном слое карты;
- подвкладки: `Изменения` и `Области`;
- один инструмент выбора работает для одного и нескольких юнитов;
- рамка используется для массового выбора, полигональная область создаётся отдельным инструментом;
- области являются переиспользуемыми объектами и хранятся в мировых координатах;
- конструктор использует трёхколоночный паттерн `категории → параметры → редактор`;
- числовые параметры используют синхронизированные slider + numeric input;
- production не должен поддерживать второй вручную скопированный каталог параметров, а должен использовать descriptor/adapter над authoritative владельцами.

Подробный контракт: `ACCEPTED_LABORATORY_V1.md`.

### Серия v1

Принят режим массового статистического прогона одного настроенного эксперимента.

Основной цикл:

`один настроенный эксперимент → много независимых прогонов → накопление результатов → статистический анализ → выбор интересного прогона → воспроизведение`.

Ключевые решения:

- при старте фиксируется замороженный снимок эксперимента;
- каждый прогон получает и сохраняет отдельный seed;
- основной UI проходит состояния `Настройка → Выполнение → Отчёт`;
- Серия использует выбранные Метрики вместо параллельного каталога измерений;
- агрегаты и распределения позволяют перейти к реальным прогонам;
- необычные прогоны являются основным сценарием анализа;
- воспроизведение конкретного запуска выполняется в обычном живом Полигоне;
- для production-воспроизводимости одного seed недостаточно: нужны замороженный experiment definition и версия/идентичность simulation runtime.

Подробный контракт: `ACCEPTED_SERIES_V1.md`.

### Правая панель v1

Принята новая каноническая правая панель поверх Series v1.1.

Роли вкладок разделены строго:

- `Юнит` — расширенная RTS-карточка выбранного бойца;
- `Инфо` — инспектор точки под курсором или зафиксированной точки карты;
- `Внимание` — текущее распределение внимания, видимость и контакты выбранного бойца;
- `Память` — субъективная картина мира, которую выбранный боец считает известной.

#### Юнит

Показываются состояние, здоровье/ранение, мораль, подавление, усталость, поза, вооружение и боекомплект. `Приказ игрока` и `Действие сейчас` являются разными блоками и не смешиваются.

#### Инфо

Не зависит от выбора юнита. Показывает координаты, высоту/уклон, поверхность, движение, маскировку/защиту, объекты и юниты около точки. Фиксация точки выполняется только через контекстное меню карты.

#### Внимание

Можно менять профиль и режим внимания. Секторная инфографика показывает углы, силу, частоту проверок, максимальную дальность и расстояние начала падения качества.

Оверлей:

- центрирован на выбранном бойце;
- совпадает с фактическим направлением его внимания;
- остаётся world-bound при zoom/pan;
- имеет плавную геометрию без клеточных ступенек;
- использует постоянный экранный размер маркеров;
- держит контактные маркеры выше слоя юнитов;
- показывает текущий контакт, прошлое наблюдение, подозрение и звук.

Production renderer должен потреблять подготовленные simulation-owned visibility/perception результаты и не запускать full-map gameplay computation из UI.

#### Память

Показывает подтверждённые контакты, прошлые контакты, предположения, разведданные и предполагаемое положение фронта.

Общая запись знания:

`тип + геометрия + время + уверенность + источник`.

Геометрия может быть точкой, точкой с неопределённостью, областью или линией/полосой.

При открытой Памяти карта приглушается одним полупрозрачным solid-слоем, а юниты и субъективные метки остаются читаемыми поверх него.

В правой панели:

- `Тип` занимает всю ширину;
- `Актуальность` ниже занимает всю ширину и задаётся ползунком;
- крайнее правое положение ползунка = `Бессрочно`;
- переключатели `Метки`, `Время`, `Названия` включены по умолчанию;
- `Источники` на карте выключены по умолчанию.

Подробный контракт всех четырёх вкладок и performance/runtime boundary: `ACCEPTED_RIGHT_PANEL_V1.md`.

## Постоянный процесс UI

1. Сначала исполнитель исследует новый крупный UI-раздел и описывает его текстом.
2. Текстом согласуются сущность, структура, сценарии, внутренние вкладки и спорные продуктовые решения.
3. До явного одобрения HTML нового раздела не создаётся и не изменяется.
4. После одобрения выполняются реализация и визуальная проверка.
5. Способ передачи большого HTML определяется явной инструкцией пользователя.
6. Для следующей итерации используется только последняя принятая каноническая версия целого Полигона.

## Runtime boundary

Standalone Polygon остаётся UX/reference-прототипом:

- production simulation и registry/config sources — authoritative;
- UI/renderer не становится владельцем gameplay truth;
- demo-history, demo-intel, demo-front и demo-data не доказывают production wiring;
- субъективные Внимание и Память должны соблюдать знания конкретного бойца;
- production adapters для Metrics, Journal, общих редакторов, Laboratory, Series и правого инспектора выполняются отдельными задачами;
- оверлеи не должны создавать один display object на каждую клетку или запускать полный игровой пересчёт карты из UI;
- standalone Series не доказывает наличие production background runner, хранилища результатов или deterministic replay.

## Что пока не готово

- production wiring Right Panel v1 к полным attention/perception/visibility/memory contracts;
- production contracts для разведданных и предполагаемой линии фронта там, где их ещё нет;
- historical perception/memory/weapon-state adapter для Journal;
- вкладки правой панели `Опасность`, `Скрытность`, `Позиции` и расширенное `Оружие`;
- production background runner для сотен/тысяч прогонов Серии;
- сохранение замороженного experiment definition, seed и simulation runtime fingerprint;
- production telemetry aggregation и хранилище результатов Серий;
- deterministic replay конкретного прогона;
- production telemetry для принятого UX Метрик;
- production Journal adapter и replay/history provider;
- production wiring standalone authoring UX общих редакторов;
- production descriptor/adapter и resolution chain для Laboratory overrides;
- сохранение Laboratory state в production experiment definition;
- правила конфликтов и приоритетов перекрывающихся Laboratory overrides;
- пространственная аналитика карты в Отчёте;
- сравнение нескольких Серий и расширенная статистика — только отдельной будущей задачей.

## Ближайшая цель

Следующие UI-итерации правой панели проектировать по одной вкладке: `Опасность`, затем другие разделы по явной задаче пользователя.

Для любого следующего UI-этапа:

1. начинать только от принятого Right Panel v1;
2. сначала согласовать интерфейс текстом;
3. только после явного одобрения менять HTML;
4. не ломать принятые редакторы, Metrics v18, Journal v4, Global Editors v1, Laboratory v1, Series v1, Right Panel v1 и систему тактических знаков;
5. runtime wiring проектировать отдельно, сохраняя simulation единственным источником игровой истины и соблюдая performance contract.

Подробная история предыдущих этапов находится в `JOURNAL.md`; точные принятые контракты — в `ACCEPTED_*.md`.
