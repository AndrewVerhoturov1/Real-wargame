# Полигон — редактор эксперимента

## Назначение

«Полигон» — подпроект Real Wargame для подготовки и проведения воспроизводимых тактических экспериментов. Центральная карта остаётся общим рабочим пространством, вокруг которого собраны редакторы карты, участников, программы, запуска и анализа результатов.

Автономные HTML-прототипы используются как UX/reference-контракты до production-подключения. Они не заменяют игровые модели, реестры и simulation runtime.

## Что уже принято

### Редактор юнита

Рабочий UX-прототип создания и настройки участника: выбор, перемещение, поворот, позы, архетипы, профили, стартовое состояние и тактический знак.

### Отображение пехоты

Пехота отображается условными знаками: круг — стоя, скруглённый треугольник — на корточках, вытянутый прямоугольник — лёжа. Сохраняются отдельное направление корпуса и оружия, тип оружия, действие, состояния и уровни детализации.

### Редактор карты

Принят авторинг поля, рельефа, поверхностей, растительности, линейных объектов, зданий и предметов, а также история действий, запекание и сохранение/загрузка результата.

### Программа

Принят редактор программы эксперимента: дорожки, шаги, действия, условия, ветвления, циклы, параллельные ветви и привязки к карте/участникам.

### Метрики v18

Принят UX полного цикла настройки измерений и последующего анализа. Measurement definition определяет поток исходных данных, а Отчёт выполняет постфактум-анализ, не меняя raw telemetry. Production telemetry wiring остаётся отдельной задачей.

### Журнал v4

Принят read-only UX причинно-временного разбора эксперимента: единая лента, фильтры, inline-подробности, глобальная хронология, LIVE/HISTORY навигация и исторический unit inspector. Production replay/history provider остаётся отдельной задачей.

### Общие редакторы v1

Принят единый popup/workbench из шапки Полигона с постоянной левой навигацией, списком сущностей/профилей и большой рабочей областью.

Состав:

**Поведение**
- `Профили маршрута`;
- `Тактические позиции`.

**Боец**
- `Архетипы бойцов`;
- `Профили внимания`;
- `Профили восприятия`;
- `Профили движения`.

**Бой**
- `Вооружение`;
- `Ранения и подавление`.

**Мир**
- `Типы поверхностей`;
- `Профили местности`;
- `Направленный рельеф`.

`Граф поведения` и `Данные бойца` по явному продуктовому решению не входят в это меню Полигона.

В **Polygon authoring mode все gameplay tuning-настройки разблокированы**, включая встроенные профили, опубликованные записи каталога вооружения и параметры, которые ещё не подключены к production runtime. При этом пометки `Ещё не подключено` и `Будущая механика` сохраняются: редактируемость UX-прототипа не означает production wiring.

Stable ID, revision/status, невозможность удалить built-in и disabled-кнопка `Сохранить` при отсутствии изменений считаются служебными ограничениями идентичности/действия, а не gameplay-lock.

Подробный контракт: `ACCEPTED_GLOBAL_EDITORS_V1.md`.

## Постоянный процесс UI

1. Сначала исполнитель исследует новый крупный UI-раздел и описывает его текстом.
2. Текстом согласуются сущность, структура, сценарии, внутренние вкладки и спорные продуктовые решения.
3. До явного одобрения HTML нового раздела не создаётся и не изменяется.
4. После одобрения выполняются реализация и визуальная проверка.
5. Большой HTML Полигона передаётся пользователю только внутри ZIP, с `answer.md` в корне архива.
6. Для следующей итерации используется только последняя принятая каноническая версия целого Полигона.

## Runtime boundary

Standalone Polygon остаётся UX/reference-прототипом:

- production simulation и registry — authoritative;
- demo-history и demo-data не доказывают production telemetry/replay wiring;
- standalone tuning не объявляется источником истины production runtime;
- production adapters для Metrics, Journal и общих редакторов выполняются отдельными задачами.

## Что пока не готово

- `Серия` как следующая крупная продуктовая вкладка;
- production telemetry для принятого UX Метрик;
- production Journal adapter и replay/history provider;
- historical perception/memory/weapon-state adapter;
- production wiring standalone authoring UX общих редакторов;
- пространственная аналитика карты в Отчёте.

## Ближайшая цель

Следующая UI-задача — `Серия`:

1. начинать только от Global Editors v1;
2. сначала согласовать интерфейс текстом;
3. только после явного одобрения менять HTML;
4. не ломать принятые редакторы, Metrics v18, Journal v4 и систему тактических знаков;
5. runtime wiring проектировать отдельно, сохраняя simulation единственным источником игровой истины.

Подробная история предыдущих этапов находится в `JOURNAL.md`; точные принятые контракты — в `ACCEPTED_*.md`.
