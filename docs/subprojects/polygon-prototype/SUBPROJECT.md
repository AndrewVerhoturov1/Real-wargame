# Полигон — редактор эксперимента

## Назначение

«Полигон» — подпроект Real Wargame для подготовки и проведения воспроизводимых тактических экспериментов. Центральная карта остаётся общим рабочим пространством, вокруг которого собраны редакторы карты, участников, программы, запуска и анализа результатов.

Автономные HTML-прототипы используются как UX/reference-контракты до production-подключения. Они не заменяют игровые модели, реестры и simulation runtime.

По явному решению пользователя сам большой HTML Series v1 этой приёмкой в репозиторий не добавляется. Подробный продуктовый и UX-контракт: `ACCEPTED_SERIES_V1.md`.

## Что уже принято

### Редактор юнита

Рабочий UX-прототип создания и настройки участника: выбор, перемещение, поворот, позы, архетипы, профили, стартовое состояние и тактический знак.

### Отображение пехоты

Пехота отображается условными знаками: круг — стоя, скруглённый треугольник — на корточках, вытянутый прямоугольник — лёжа. Сохраняются отдельное направление корпуса и оружия, тип оружия, действие, состояния и уровни детализации.

### Редактор карты

Принят авторинг поля, рельефа, поверхностей, растительности, линейных объектов, зданий и предметов, а также история действий, запекание и сохранение/загрузка результата.

### Программа

Принят редактор программы эксперимента: дорожки, шаги, действия, условия, ветвления, циклы, параллельные ветви и привязки к карте/участникам.

### Метрики v18

Принят UX полного цикла настройки измерений и последующего анализа. Measurement definition определяет поток исходных данных, а Отчёт выполняет постфактум-анализ, не меняя raw telemetry. Production telemetry wiring остаётся отдельной задачей.

### Журнал v4

Принят read-only UX причинно-временного разбора эксперимента: единая лента, фильтры, inline-подробности, глобальная хронология, LIVE/HISTORY навигация и исторический unit inspector. Production replay/history provider остаётся отдельной задачей.

### Общие редакторы v1

Принят единый popup/workbench из шапки Полигона с постоянной левой навигацией, списком сущностей/профилей и большой рабочей областью.

Состав:

**Поведение**
- `Профили маршрута`;
- `Тактические позиции`.

**Боец**
- `Архетипы бойцов`;
- `Профили внимания`;
- `Профили восприятия`;
- `Профили движения`.

**Бой**
- `Вооружение`;
- `Ранения и подавление`.

**Мир**
- `Типы поверхностей`;
- `Профили местности`;
- `Направленный рельеф`.

`Граф поведения` и `Данные бойца` по явному продуктовому решению не входят в это меню Полигона.

В **Polygon authoring mode все gameplay tuning-настройки разблокированы**, включая встроенные профили, опубликованные записи каталога вооружения и параметры, которые ещё не подключены к production runtime. При этом пометки `Ещё не подключено` и `Будущая механика` сохраняются: редактируемость UX-прототипа не означает production wiring.

Stable ID, revision/status, невозможность удалить built-in и disabled-кнопка `Сохранить` при отсутствии изменений считаются служебными ограничениями идентичности/действия, а не gameplay-lock.

Подробный контракт: `ACCEPTED_GLOBAL_EDITORS_V1.md`.

### Лаборатория v1

Принят новый основной раздел для временных экспериментальных overrides. Основная сущность: `параметр + экспериментальное значение + цель/область действия`.

Ключевые решения:

- Лаборатория не меняет верхнюю шапку и правую панель;
- в левой панели используются подвкладки `Изменения` и `Области`;
- набор кнопок инструментов меняется по контексту аналогично редактору карты;
- один инструмент выбора работает и для одного, и для нескольких юнитов;
- рамка используется только для массового выбора юнитов;
- полигональные области создаются отдельным инструментом и являются переиспользуемыми объектами;
- геометрия областей хранится в координатах карты и остаётся привязанной к местности при zoom/pan;
- клик по override открывает подробности в левой панели и подсвечивает точную цель;
- контекстное меню поддерживает работу с юнитами, группами, областями и диагностикой действующих overrides;
- конструктор построен по компактному трёхколоночному паттерну Метрик: категории → каталог параметров → редактор выбранного параметра;
- отдельного wizard `Параметр / Цель / Значение` нет;
- числовые параметры редактируются через синхронизированные slider + numeric input;
- каталог и правая колонка конструктора сохраняют независимую позицию прокрутки при локальных действиях;
- Лаборатория не создаёт второй вручную поддерживаемый каталог игровых параметров и в production должна опираться на descriptor/adapter layer над настоящими владельцами параметров;
- `Применить глобально` допустимо только при наличии однозначного постоянного authoritative owner.

Подробный контракт: `ACCEPTED_LABORATORY_V1.md`.

### Серия v1

Принят отдельный режим массового статистического прогона одного настроенного эксперимента.

Основной цикл:

`один настроенный эксперимент → много независимых прогонов → накопление результатов → статистический анализ → выбор интересного прогона → воспроизведение`.

Ключевые решения:

- при старте Серии фиксируется замороженный снимок эксперимента;
- каждый прогон получает отдельный случайный seed, который сохраняется вместе с результатом;
- основной UI не раскрывает технические настройки потоков/workers;
- состояние вкладки проходит естественные этапы `Настройка → Выполнение → Отчёт`;
- во время выполнения видны прогресс, выполнено/осталось, ошибки, скорость, пауза/остановка и формирующиеся предварительные результаты;
- Серия использует выбранные Метрики вместо создания отдельного каталога измерений;
- большой отчёт показывает агрегаты и распределения по множеству прогонов;
- распределения являются интерактивным способом перейти от агрегата к конкретным прогонам;
- каждый прогон хранит ID, seed, результат и значения выбранных Метрик;
- список прогонов поддерживает отбор по условиям на основе Метрик;
- необычные прогоны показываются и в кратком обзоре, и отдельным полноценным разделом `Необычные` в большом отчёте;
- для необычного запуска сохраняются причина выделения, сравнение со всей Серией, seed, подробности и действие `Воспроизвести прогон`;
- исправленный сценарий v1.1 возвращает после воспроизведения к тому же выбранному необычному прогону;
- воспроизведение конкретного запуска выполняется в обычном живом Полигоне, а не внутри статистического интерфейса Серии;
- завершённые Серии сохраняются в истории как результаты исследования.

Для production детерминированного воспроизведения одного seed недостаточно: необходимо также сохранять замороженный experiment definition и версию/идентичность simulation runtime.

Подробный контракт: `ACCEPTED_SERIES_V1.md`.

## Постоянный процесс UI

1. Сначала исполнитель исследует новый крупный UI-раздел и описывает его текстом.
2. Текстом согласуются сущность, структура, сценарии, внутренние вкладки и спорные продуктовые решения.
3. До явного одобрения HTML нового раздела не создаётся и не изменяется.
4. После одобрения выполняются реализация и визуальная проверка.
5. Способ передачи большого HTML определяется явной инструкцией пользователя; по умолчанию используется ZIP-архив.
6. Для следующей итерации используется только последняя принятая каноническая версия целого Полигона.

## Runtime boundary

Standalone Polygon остаётся UX/reference-прототипом:

- production simulation и registry/config sources — authoritative;
- demo-history и demo-data не доказывают production telemetry/replay wiring;
- standalone tuning, Laboratory overrides и Series statistics не объявляются источником истины production runtime;
- production adapters для Metrics, Journal, общих редакторов, Laboratory и Series выполняются отдельными задачами;
- standalone Series v1 не доказывает наличие production background runner, хранилища результатов или deterministic replay.

## Что пока не готово

- production background runner для сотен/тысяч прогонов Серии;
- сохранение замороженного experiment definition, seed и simulation runtime fingerprint;
- production telemetry aggregation и хранилище результатов Серий;
- deterministic replay конкретного прогона;
- production telemetry для принятого UX Метрик;
- production Journal adapter и replay/history provider;
- historical perception/memory/weapon-state adapter;
- production wiring standalone authoring UX общих редакторов;
- production descriptor/adapter и resolution chain для Laboratory overrides;
- сохранение Laboratory state в production experiment definition;
- правила конфликтов и приоритетов перекрывающихся Laboratory overrides;
- пространственная аналитика карты в Отчёте;
- сравнение нескольких Серий и расширенная статистика — только отдельной будущей задачей.

## Ближайшая цель

Новая крупная UI-вкладка после Series v1 пока не назначена.

Для любого следующего UI-этапа:

1. начинать только от принятого Series v1;
2. сначала согласовать интерфейс текстом;
3. только после явного одобрения менять HTML;
4. не ломать принятые редакторы, Metrics v18, Journal v4, Global Editors v1, Laboratory v1, Series v1 и систему тактических знаков;
5. runtime wiring проектировать отдельно, сохраняя simulation единственным источником игровой истины.

Для production Серии ближайший технический блок — background runner + сохранение снимка/seed/runtime fingerprint + агрегирование Метрик + воспроизведение конкретного прогона.

Подробная история предыдущих этапов находится в `JOURNAL.md`; точные принятые контракты — в `ACCEPTED_*.md`.
