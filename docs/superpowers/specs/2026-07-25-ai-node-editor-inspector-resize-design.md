# Переработка связей, палитры и инспектора редактора ИИ

## Статус

Согласовано пользователем 2026-07-25 как продолжение ветки `feature/20260725-ai-node-editor-ux`.

## Цель

Довести ежедневную работу в редакторе ИИ до единой и предсказуемой модели:

- удалять связи с обеих сторон;
- выбирать типы нод компактным выпадающим списком;
- редактировать ноду только через один видимый пользовательский интерфейс;
- привести инспектор к единой визуальной системе;
- менять и постоянно сохранять ширину палитры и инспектора.

## Границы

- Graph v2 и формат JSON графа не меняются.
- Выполнение ИИ, симуляция, игра и поведение нод не меняются.
- Избранное, ширины панелей и фильтр палитры остаются пользовательскими настройками и не входят в JSON графа.
- Работа продолжается в существующей feature-ветке и PR №173.
- Новый деплой не входит в эту задачу без отдельного явного запроса.

## 1. Симметричное удаление связей

### 1.1. Управляющие связи

Правый управляющий выход ноды показывает занятое состояние, если у ноды есть дочерние ноды.

Рядом с занятым выходом находится отдельная кнопка удаления:

- при одной исходящей связи она удаляет именно эту связь;
- при нескольких связях открывает компактное меню целей;
- меню позволяет удалить одну выбранную связь или все управляющие связи этого выхода.

### 1.2. Типизированные связи данных

Каждый типизированный выход проверяет реальные `inputBindings` других нод.

Если выход используется:

- порт отмечается как занятый;
- рядом появляется отдельная кнопка удаления;
- при одном потребителе удаляется точная привязка входа;
- при нескольких потребителях открывается меню со списком `targetNode.inputPort` и командой удаления всех потребителей этого выхода.

### 1.3. Общая команда исходящих связей

Команда контекстного меню «Удалить исходящие связи» удаляет:

- все `children` выбранной ноды;
- все типизированные входные привязки других нод, которые ссылаются на выбранную ноду.

Кнопки удаления изолируют `pointerdown` и `click`, поэтому не начинают перетаскивание ноды, панорамирование графа или новую связь.

## 2. Выпадающий фильтр палитры

Полоса кнопок категорий заменяется одним `<select>`.

Пункты:

- Все типы;
- Избранное;
- Управление;
- Условия;
- Оценки;
- Запросы;
- Действия;
- Память;
- Подграфы;
- Отладка.

Поиск остаётся отдельным полем и применяется совместно с выбранным пунктом.

Текущий `paletteFilter` продолжает сохраняться в `real-wargame.ai-node-editor.ui.v6`. Избранное продолжает сохраняться отдельно и постоянно.

## 3. Один видимый редактор ноды

### 3.1. Основной интерфейс

Единственным видимым редактором параметров становится существующий человеческий интерфейс ноды.

Он содержит:

- компактный заголовок ноды;
- специализированные параметры конкретного типа;
- дополнительные панели длительных и специальных нод;
- общую задержку;
- сворачиваемые название и описание;
- одну основную кнопку «Сохранить ноду»;
- сворачиваемый технический JSON только для просмотра.

### 3.2. Совместимость старых интеграций

Старый общий блок «Редактирование» полностью исчезает с экрана.

Для существующих модулей `stateful-node-ui.ts`, `AttentionNodeControls.ts` и других интеграций сохраняется невидимый технический мост:

- `#node-display-name`;
- `#node-display-name-ru`;
- `#node-description`;
- `#node-description-ru`;
- `#node-parameters`;
- `#save-node`.

Человеческий интерфейс синхронизирует значения с этим мостом и вызывает общий проверенный путь сохранения. Пользователь при этом видит только одну систему и одну кнопку.

## 4. Новый дизайн инспектора

Инспектор строится сверху вниз:

1. компактная шапка панели;
2. краткая карточка выбранной ноды с ID, типом и категорией;
3. единый человеческий редактор;
4. компактная секция связей;
5. свёрнутая диагностика вычисления;
6. небольшая опасная зона.

Правила оформления:

- единая высота обычных полей и кнопок;
- кнопки не растягиваются на всю ширину без необходимости;
- основное действие одно и визуально выделено;
- второстепенные действия компактные;
- технические сведения свёрнуты;
- карточки используют одинаковые радиусы, отступы и заголовки;
- интерфейс остаётся работоспособным при минимальной ширине инспектора.

## 5. Изменяемая ширина панелей

### 5.1. Палитра

На правой границе открытой палитры находится вертикальная область перетаскивания.

- минимум: 180 px;
- стандарт: 228 px;
- максимум: 420 px.

### 5.2. Инспектор

На левой границе открытого инспектора находится вертикальная область перетаскивания.

- минимум: 260 px;
- стандарт: 300 px;
- максимум: 520 px.

### 5.3. Поведение

- курсор над границей — `col-resize`;
- размер меняется без полного перерисовывания DOM на каждом пикселе;
- минимальная ширина графа — 520 px;
- итоговый размер сохраняется после `pointerup`;
- ширины хранятся в `real-wargame.ai-node-editor.ui.v6`;
- закрытие и повторное открытие панели не сбрасывает размер;
- ошибочные или старые значения из `localStorage` ограничиваются допустимым диапазоном;
- при 1440×900 нет общего горизонтального или вертикального прокручивания страницы.

## 6. Проверки

### Автоматические

Статический UX-smoke должен подтверждать:

- наличие выпадающего фильтра и отсутствие прежней полосы кнопок;
- наличие постоянных ширин в UI state;
- наличие двух разделителей панелей;
- точное и массовое удаление управляющих и типизированных исходящих связей;
- удаление всех видов исходящих связей через контекстное меню;
- отсутствие видимого дублирующего блока редактирования;
- наличие невидимого совместимого моста;
- одну видимую кнопку сохранения в человеческом интерфейсе.

После реализации запускаются TypeScript, профильные smoke-проверки редактора и production build через разрешённый GitHub Actions процесс.

### Визуальные

Скриншоты 1440×900 должны показать:

1. полный редактор со стандартными ширинами;
2. палитру с выпадающим фильтром;
3. расширенную палитру и суженный инспектор;
4. суженную палитру и расширенный инспектор;
5. единый инспектор без дублирующего редактора;
6. меню удаления нескольких исходящих связей.

Проверяется отсутствие общего переполнения, единый размер элементов, доступность основных действий и сохранение рабочего пространства графа.
